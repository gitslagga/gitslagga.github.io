如何实现一个超级域名网站

要求：给每个用户分配唯一的二级域名，用户又可以创建三级域名

核心思路是：所有子域名都指向同一个入口，应用根据请求的 Host 判断当前用户和用户创建的站点。

假设主域名为 example.com：

  • 用户域名：alice.example.com
  • 用户创建的下级域名：blog.alice.example.com
  • 管理域名：admin.example.com

六、创建域名时的校验

域名标签建议限制为：

还需要：

  • 转换为小写。
  • 长度不超过 63 个字符。
  • 禁止连续或首尾连字符。
  • 保留 www、admin、api、mail 等系统名称。
  • 数据库增加唯一约束，防止并发抢注。
  • 创建接口增加限流。
  • 禁止 Unicode 混淆字符，或先经过 IDNA/Punycode 规范化。
  • 删除用户时不要立刻释放域名，避免钓鱼和账户冒充。

推荐落地方案

如果用户规模还不大：

  • Next.js 负责多租户路由。
  • PostgreSQL 保存用户与子域名映射。
  • Cloudflare 管理 DNS。
  • 用户创建三级域名时调用 Cloudflare API 创建具体记录。
  • TLS 交给 Cloudflare或 Caddy 管理。
  • Redis 缓存 hostname → siteId，减少每次请求查询数据库。

真正困难的并不是页面路由，而是多级域名的 TLS、DNS 自动化、域名抢注和租户隔离。先把 alice.example.com 做稳定，再加入 blog.alice.example.com，会更容易控制复杂度。
